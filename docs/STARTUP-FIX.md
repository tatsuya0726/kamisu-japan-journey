# Startup repair

The initial HTML exposed battle controls and an empty battlefield. Phaser preloaded 19 full-size PNGs before create() called home(), so a slow image response delayed the title indefinitely from the user's perspective. Save restoration was not the cause: only cleared stages and preferences are stored.

- An inline, image-independent tap-to-start shell now appears before the module loads. Battle UI remains hidden until the user taps to enter the ready title. After 12 seconds a failed/slow script shows an explicit reload button, without clearing saves.
- Phaser startup loads no images. The tap screen becomes interactive without waiting for artwork; a user gesture unlocks audio and opens the title. Ten card images are mounted only on departure.
- Title art is preloaded from the HTML; first-battle art loads behind the tap screen. Other battle backgrounds load on departure and the seven visit backgrounds load on entry. Each request has an 8-second timeout, the batch has a 12-second deadline, and fallback art remains playable. No automatic retry loop. A visible manual image retry is limited to once per page session; subsequent user-initiated departures can load missing art.
- DOM image requests get an 8-second fallback. Decorative CSS backgrounds never gate navigation.
- 27 derived assets use 384px transparent PNG sprites and 1024px JPEG scenery at quality 82. Approved originals (40,813,685 bytes) remain unchanged. Runtime art totals 4,158,103 bytes: an 89.8% reduction. The three prioritized title images total 615,208 bytes. Cold local HTTP measurements recorded 19 unique initial image requests, 3,054,966 bytes including the home-screen icon, no duplicate image requests, and zero visit backgrounds. Entering battle and all seven visits reused cats/map from browser cache; each visit background was requested once. A discovered relative CSS-variable background URL was corrected to an absolute URL.
- Card portraits now have absolute inset dimensions and cards have a minimum height, preventing percentage-height collapse into thin strips.

## Validation

43 automated tests passed (including deadline/error/success image fallback tests) and TypeScript/production build passed. A dedicated local fault server serves the same production output: images delayed 20 seconds, all images 404, and module JavaScript 404. Slow/failed images did not block title, map, departure or cat deployment. Batch loading status ended in fallback. Missing JavaScript retained the title and revealed a reload action. Fresh origin showed all stages uncleared; existing local saves retained stage 0 and 2 clears. Reload from battle returned to title. At 667x375, 844x390, 1280x720 and 1920x1080, tap/title buttons remained inside the viewport, no page horizontal overflow, and all ten portraits loaded. At 667x375, all ten card images loaded and had at least 52px display height (artist intentionally scaled). Normal battle artwork visually checked. Screenshots remain in ignored Captures/.

Limit: these are desktop Chrome responsive and fault-injection checks, not a physical phone or actual mobile-radio test. Phaser bundle remains ~358 KB gzip; the static title covers its load and reports prolonged startup.

Home-screen support: manifest with relative scope/start URL, standalone display and landscape preference; 192/512 icons and iOS metadata. No service worker or stale offline cache. The requested landscape/home-screen message is shown on the tap screen. Browser/OS support governs installation and orientation; no forced rotation or orientation-unlock promise. Audio context activation, BGM pause, mute toggle and effect trigger were checked; physical speaker output was not independently recorded.
